# Workshop Part 2 — The Core Mechanic (Spielmechanismus)

> **Source:** Making Games Magazin 04/2010, pp. 40–42 · **Author:** Daniel Dumont
> **Use:** Background for skills supporting `02_CoreMechanic.md`

---

## TL;DR

The Core Mechanic is the **most important recurring action flow** and the **actual fun**. It is realized by a set of mutually reinforcing features. Identifying it correctly is the single biggest leverage for the rest of the concept: features that bind to it gain meaning; features that don't are emotional dead-ends and can be cut.

---

## Agent Cheat Sheet

### Definition (verbatim)

> The core mechanic is the most important action flow in a game and represents the actual fun factor. It is realized through a series of mutually coordinated game features and, in the ideal case, embellished by many further features.

### Three diagnostic questions (agent must ask)

1. **What does the player do repeatedly?** (the action loop)
2. **Why does that feel good?** (the psychological hook)
3. **Which features make this loop deeper, longer-lasting, or harder to master?** (the binding features)

### Mechanic vs. non-mechanic

| Counts as mechanic | Does **not** count |
|---|---|
| Active player action loop | Beautiful landscapes |
| Repeated decision/skill expression | Special effects |
| Story (exception — pulls player through "passive activity") | Atmosphere |
| | Single one-off features unbound to a loop |

### Psychological hooks (which one does the mechanic target?)

| Hook | Example game | Player feels |
|---|---|---|
| Foresight / planning | Puzzle games | "I think many moves ahead" |
| Skill expression / power | Shooters | "I outreacted my opponent" |
| Status / display | WoW | "I outrank weaker players" |
| Creation / admiration | Anno, city builders | "I built this" |
| Mastery of physics | Flight simulators | "I control complex systems" |

Underlying theme: **be something special, mentally on top.**

### Failure modes

| Failure | Diagnostic | Fix |
|---|---|---|
| Mechanic too simple | No challenge → no sense of achievement | Add depth or skill ceiling |
| Mechanic exists but delivery rough | Bad maps, dumb AI, rough controls, poor graphics | Fix delivery — mechanic is fine |
| "Cool but unrelated" feature list | Many features, no unifying loop | Identify the central action; rank others |
| Atmosphere mistaken for mechanic | "Great graphics" named as mechanic | Reclassify as addition |
| Multiple mechanics, none committed | Writer says "depends" | Force ranking; commit to one primary |

### Feature binding rules

| Binding strength | Treatment |
|---|---|
| Strongly bound to mechanic | Keep, elaborate, allocate dev effort |
| Weakly bound | Cut or downgrade to "nice to have" |
| Unbound | Cut without regret |
| Bound to weak secondary mechanic | Allocate fewer/cheaper features |
| Bound to strong primary mechanic | Allocate many/elaborate features |

### Test for new feature additions

> Q: How does this feature bind to the core mechanic?
> If answer is weak → push back or downgrade.

---

## Worked example: Fallout 3 "Loot, Compare, Equip"

| Feature | Role |
|---|---|
| 1. World is explorable | Provides space for the loop |
| 2. Monsters to kill | Source of reward |
| 3. Monsters drop loot, comparable to inventory | The compare step |
| 4. Item system with many items, trade-offs, values, prices | Makes comparison meaningful |

Break one feature (e.g., enemies drop too much loot) → mechanic stops motivating.

## Worked example: shooter binding

Single mechanic: *react fast → aim precisely → shoot*.

| Binding feature | Standalone value | Bound value |
|---|---|---|
| Reload | Boring | Essential — without it the loop stops |
| Limited ammo + pickup | Nuisance | Tactical layer |
| Dodge / take cover | Generic | Critical movement decision |
| Weapon switching | Menu friction | Tactical choice |
| Fast combat movement | Generic | Direct skill expression |

### What is NOT in the mechanic

| Feature | Why excluded | Note |
|---|---|---|
| Weapon jamming (Stalker) | Disrupts loop, serves authenticity | Goal-specific, not mechanic |
| Same jamming if player controls it (sustained fire only) | Now part of loop | Becomes mechanic-bound |

## Worked example: weak feature rescued by binding

| Feature | Standalone | Bound to | Bound value |
|---|---|---|---|
| Plant gathering (RPG) | Boring, pointless | "Level up the hero" via permanent-stat potions | Becomes highly motivating |

## When to commit to mechanics

| Situation | Action |
|---|---|
| Stage 1 (Game Idea) | Commit to **one** primary mechanic, statable in one sentence |
| Established genre | Adopt the genre's proven mechanic. Name and analyze it explicitly |
| Multiple mechanics planned | Rank by importance. Stronger gets more features |
| New mechanic concept | State it concisely, then test with diagnostic Q1+Q2 |
